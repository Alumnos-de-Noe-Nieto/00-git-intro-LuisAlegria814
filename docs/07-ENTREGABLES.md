```markdown
# Alumno: Paula Gómez García

**Número de Control:** 202412345

## ¿Qué es Git?

Git es un sistema de control de versiones que permite a los programadores guardar
cambios en su código, ver el historial de modificaciones y colaborar con otros
sin perder trabajo. Es como un "save point" automático para tu código.

## Por qué necesitamos Git

Sin Git, cuando trabajamos en equipo varios compañeros editando el mismo proyecto,
alguien sobrescribe el trabajo del otro, se pierden cambios y no sabemos quién
hizo qué. Git resuelve esto permitiendo que todos trabajen en paralelo sin conflictos.

## Los 3 conceptos clave de Git

1. **Repositorio:** La carpeta de tu proyecto que Git vigila y donde guarda todo el
   historial con la carpeta especial .git

2. **Commit:** Un "punto de guardado" en tu código con los cambios que hiciste, un
   mensaje describiendo qué hiciste, y marcado con una hora exacta.

3. **Rama:** Una línea de desarrollo separada. La principal se llama main, pero puedes
   crear ramas para experimentar sin afectar el código principal.

## Los comandos que aprendí

- `git init` - Inicializa Git en una carpeta (crea la carpeta .git)
- `git add` - Prepara los cambios para guardar
- `git commit` - Guarda los cambios con un mensaje
- `git push` - Sube tus cambios a GitHub (servidor)
- `git pull` - Descargas cambios de tus compañeros desde GitHub

## Mi reflexión final

Lo más importante que aprendí de Git es que la colaboración sin control de versiones
es casi imposible cuando trabajas en equipo. Git no solo resuelve problemas técnicos,
sino que también documenta quién hizo cada cambio y cuándo, lo que es muy importante
en proyectos profesionales. Ahora puedo trabajar con mis compañeros sin miedo a perder
código o sobrescribir su trabajo.

**Fecha:** 5 de febrero de 2026
```

## 🚨 Errores Comunes

### ❌ Error 1: El archivo no sube a GitHub

**Problema:** Hiciste `git push` pero el archivo no aparece en GitHub

**Solución:**
```bash
git status        # Verifica que ALUMNO.md aparezca en "Changes to be committed"
git log --oneline # Verifica que el commit se hizo
git push          # Repite el push (asegúrate de que no hay errores)
```

---

### ❌ Error 2: Copié del internet

**Problema:** Tu reflexión tiene exactamente las mismas palabras que Wikipedia

**Resultado:** Tu profesor lo detectará. Escribe en tus propias palabras.
